# ЛАБИРИНТ — многопользовательская 3D-бродилка

Онлайн-хоррор-бродилка по лабиринту 49×49: найдите **5 ключей**, откройте **дверь зала в центре** и не попадитесь Привидению и скелетам. Играется компанией до 16 человек на одной карте — с чатом, hi-score и общим миром.

Рендер сделан с нуля, без игровых движков: **софтверный рейкастинг** в стиле Wolfenstein 3D — картинка рисуется попиксельно в canvas 480×270 и растягивается с сохранением «пиксельности». Звук тоже без файлов — всё синтезируется через WebAudio (шаги, шёпот, сердцебиение, скримеры).

## Быстрый старт

```bash
npm install
npm start          # или: node server.js
```

Откройте [http://localhost:3000](http://localhost:3000). Порт меняется переменной окружения `PORT`:

```bash
# Windows
set PORT=8080 && npm start
# Linux / macOS
PORT=8080 npm start
```

Для разработки с автоперезапуском: `npm run dev` (nodemon).

**Требования:** Node.js ≥ 18. Зависимости: `express`, `ws`; для разработки — `nodemon`.

## Как играть

- Карта 49×49 генерируется на сервере (алгоритм DFS со случайными проломами) и одинакова для всех.
- В центре лабиринта — **зал с дверью**: собираете 5 ключей, подходите к двери — она открывается, игра заканчивается для всех с экраном победителя.
- **Привидение** у каждого игрока своё: патрулирует, слышит бег, преследует по кратчайшему пути (BFS), замирает, когда игрок смотрит прямо на него (в пределах 10 клеток).
- **Скелеты** (40 шт.) общие для всех: бродят по лабиринту, игрока не ищут, но замечают в прямой видимости на 9 клеток и атакуют. Убиваются дробовиком — **2 попадания**, дальность 7.2 клетки, перезарядка 0.5 с. Если несколько скелетов сбились в одну кучу, над ней показывается янтарная цифра — сколько их вместе (одиночек не подписываем). Кости скелета **бежевые** (`#e8d9b0`) и подчиняются свету фонаря, Привидение — холодное сине-белое и светится само: так врагов нельзя спутать в темноте.
- **Патроны**: в запасе не больше 30 выстрелов. По карте разбросаны призы-патроны (+30), работают как батарейки — через 30 секунд после подбора снова появляются на том же месте.
- **Предметы** у всех на одинаковых местах (расставляет сервер), но собирает каждый свой экземпляр. Батарейки, патроны и аптечки через 30 секунд после подбора появляются на том же месте снова; ключи — без респавна.
- **След памяти**: в клетках, где игрок уже стоял, потолок светлее — возвращаясь назад, видно, где ты уже прошёл. След ведётся локально у каждого игрока, живёт до конца забега (при возрождении сохраняется, при новой карте сбрасывается).
- Победа открывает дверь, +5000 очков открывшему, и всем показывается имя победителя. «Новый забег» перегенерирует карту и сбрасывает счёт.
- При смерти игрок возрождается на выданном спавне: здоровье, фонарик и патроны восстанавливаются, а найденные ключи и очки остаются с ним; уже подобранные предметы на карту не возвращаются.

### Очки

| Событие | Очки |
|---|---|
| Новая открытая клетка лабиринта (туман войны у каждого свой) | +5 |
| Ключ | +250 |
| Убитый скелет | +50 |
| Батарейка / аптечка | +20 / +30 |
| Открытая дверь (конец раунда) | +5000 |

Счёт ведёт сервер (защита от спама и превышения лимитов), live-таблица «HI-SCORE · ИГРОКИ И ОЧКИ» — в сайдбаре у каждого игрока.

### Сложность

| Режим   | Урон | Дальность зрения | Время «слежения» после потери |
|---------|------|------------------|-------------------------------|
| Лёгкая  | 22   | 5 клеток         | 3.5 с                         |
| Обычная | 40   | 8 клеток         | 2.5 с                         |
| Сложная | 60   | 13 клеток        | 1.5 с                         |

Скорость Привидения от сложности не зависит — 1.9 клетки/с, как у скелетов.

## Управление

| Клавиша | Действие |
|---------|----------|
| `W` `A` `S` `D` | Движение |
| ПКМ (зажать) | Бег — быстрее, но Привидение слышит вас дальше (9 клеток вместо 4.5) |
| ЛКМ | Выстрел дробовика: 7.2 клетки, прямая видимость; скелету нужно 2 попадания, перезарядка 0.5 с |
| `Пробел` | Выстрел (дублирует ЛКМ) |
| `F` | Фонарик вкл/выкл |
| `←` `→` | Поворот |
| Мышь | Обзор (клик по экрану захватывает курсор) |
| `Enter` | Чат |
| `Esc` | Пауза |

Настройки в стартовом окне: чувствительность мыши (0.5–4), FOV (50–100°), громкость, **режим мыши** (захват курсора / курсорный — для RDP). Сохраняются в `localStorage`.

### Сервер (`server.js`)

- Генерация лабиринта **49×49** (сетки 24×24 клеток), типы блоков: пол, кирпич, граница, «металл», **дверь (4)**.
- **Зал 3×3 в центре** с кольцом стен и единственным входом — дверью; связность лабиринта не нарушается (кольцо стоит только на чётных координатах).
- Предметы (5 ключей в дальних тупиках, 6 батареек, 8 призов-патронов, 4 аптечки) расставляет сервер — у всех игроков они на одинаковых местах.
- **Скелеты**: 40 шт., симулируются на сервере 10 раз/с — патруль по случайным целям, погоня за игроком в прямой видимости (< 9 клеток), скорость 1.9 клеток/с. Движение по путевым точкам (центрам клеток BFS-пути) со скольжением вдоль стен — скелеты не застревают на поворотах; вплотную к игроку идут прямо на него и атакуют. Спавн равномерный по всей карте: каждый скелет встаёт в самую удалённую от уже стоящих точку (farthest-point sampling по всем проходимым клеткам), при этом новые скелеты не появляются ближе 4 клеток к игрокам — и на старте, и при респавне, так что двое скелетов не могут оказаться в одной точке. Убиваются двумя попаданиями дробовика (попадания, дистанцию и видимость проверяет сервер), респавн через 20 с тоже подальше от всех.
- Рассылка снапшотов состояний **30 раз в секунду** (игроки + скелеты); клиент шлёт свою позицию с той же частотой.
- **Очки считает сервер**: батчи исследования (+5/клетка с лимитом 2401 на раунд), ключи/подборы/убийства с анти-спамом 100 мс, победа +5000.
- Серверная валидация движения: запрет телепортации (скорость ≤ 6 клеток/с) и прохода сквозь стены (коллизия с радиусом игрока 0.22).
- Heartbeat: сервер пингует сокеты каждые 15 с и принудительно закрывает молчащие — «мёртвые» клиенты (сон ноутбука, обрыв RDP/Wi-Fi) не занимают слоты.
- Санитизация имён (макс. 16 символов) и чата (макс. 120 символов); лимит пакета WebSocket 4 КБ; таймаут на join 10 с; перегенерация карты — не чаще раза в 3 с.
- Одновременных игроков — до 16.

### Клиент (`public/client.js`)

Основные модули (секции в файле): процедурные текстуры и спрайты → аудио (WebAudio-синтез) → сеть → туман войны → предметы → BFS-поиск пути → ИИ Привидения → рейкаст-рендер → UI. Настройки и константы вынесены в начало файла (`VIEW_W`, `PLAYER_SPEED`, `NET_HZ` и т.д.).

- Текстуры стен/пола/потолка/двери — 128×128 (`TS`), спрайты — 128×128 (`SPR_SIZE`). Генераторы написаны в исходных координатах 64×64 и масштабируются коэффициентом (`S = TS/64`, `g.scale` для спрайтов), поэтому при смене разрешения рисунок кладки, плитки и швов сохраняет пропорции — растёт только детализация.

- Два режима мыши (переключатель «Режим мыши» в стартовой панели, сохраняется в `localStorage`):
  - **ЗАХВАТ КУРСОРА** — pointer lock; дельта мыши применяется 1:1 (поворот = смещение × чувствительность), без потолка угловой скорости — одно движение мыши даёт ровно свой поворот, поэтому разворот в тупике срабатывает сразу, а не «докручивается» несколькими движениями. Медленные движения идут так же точно. Захват пытается включить `unadjustedMovement` с тихим откатом.
  - **КУРСОР (RDP)** — без pointer lock: скорость поворота пропорциональна смещению видимого курсора от центра экрана (мёртвая зона в центре, сглаживание), до ~240°/с — разворот на 180° примерно за 0.75 с. Для RDP, где `movementX` то приходит скачками по 700+ px, то обнуляется при живом потоке событий.
  - Счётчики мыши для диагностики доступны в консоли: `window.__mouseTel`.
- Дробовик от первого лица — по центру экрана, ствол направлен в прицел; при выстреле отдача, вспышка у дула и **след от пули на стене** (до 60 следов, по 3 на грань, очищаются при новой карте).
- Позиции чужих игроков интерполируются между снапшотами (30 Гц), поэтому спрайты двигаются плавно.
- Кнопка «НОВЫЙ ЗАБЕГ» запрашивает у сервера новую общую карту: лабиринт перегенерируется и все игроки расселяются по новым спавнам. Игроки в паузе остаются в паузе — мир обновится за оверлеем.

## Протокол WebSocket

Все сообщения — JSON.

**Клиент → сервер:** `join {name}`, `move {x, y, dirX, dirY}`, `chat {text}`, `newMap`, `explore {n}`, `key`, `pickup {kind}`, `skeletonHit {id}`, `win`, `ping {t}`.

**Сервер → клиенту:** `init {id, name, map {w, h, cells, door, items}, spawn, players, skeletons, maxPlayers}`, `state {t, players, skeletons}`, `playerJoined`, `playerLeft`, `newMap`, `gameEnd {winner, winnerId, score}`, `chat {id, name, text}`, `pong`, `error`.

Сообщения `chat` и `newMap` рассылаются всем; отправитель чата получает свою строку только через локальный эхо (без дубля по сети).

Мониторинг: `GET /health` → `{"ok":true,"players":N,"max":16}`.

### Тесты

Смоук-тест протокола (join, карта/дверь/предметы/скелеты, очки и их защита, win/gameEnd, newMap со сбросом, чат, анти-телепорт, ping/pong, heartbeat, playerLeft):

```bash
node tools/ws-smoke-test.js          # сервер должен быть запущен
# другой порт: set TEST_PORT=8080&& node tools/ws-smoke-test.js
```

Тест палитры спрайтов (скелет бежевый и тёплый, Привидение осталось холодным,
разница по тону R−B ≥ 20, корректное освещение) — сервер не нужен:

```bash
node tools/sprite-color-test.js      # 14 проверок
```

## Примечания

- Статика отдаётся без `maxAge` — только ETag/Last-Modified (304-ревалидация), поэтому после правок `client.js` браузер всегда получает свежую версию.
- Проект — не git-репозиторий; данные не хранятся, состояние игры живёт только в памяти сервера.
